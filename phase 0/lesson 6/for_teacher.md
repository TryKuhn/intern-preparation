0–5 мин. Зачем это всё.
Обсуди: GC даёт удобство, но ценой непредсказуемых пауз и накладных расходов. C++ даёт детерминированное освобождение ресурсов — критично для real-time систем, встраиваемых, высоконагруженных серверов. Именно поэтому умные указатели (следующий урок) — не просто удобство, а идиома RAII.

5–25 мин. new/delete — основы.
```cpp
int* p = new int(42);       // выделить один int на куче
delete p;                    // освободить
p = nullptr;                 // хорошая практика — убрать висячий указатель

int* arr = new int[10];      // массив
delete[] arr;                // для массива — обязательно delete[]!
```
Покажи утечку: выдели память, не освобождай, запусти под valgrind — увидит утечку.
Покажи double-free: два `delete p` подряд — UB, обычно crash или heap corruption.
Покажи use-after-free: `delete p; *p = 5;` — UB.

25–50 мин. Классические баги.
1. **Утечка**: `new` без `delete` в ветке с исключением или ранним return.
2. **Висячий указатель (dangling)**: `delete p;` — указатель всё ещё хранит старый адрес, обращение к нему — UB.
3. **Double-free**: вызвать `delete p` дважды. Показать вывод sanitizer.
4. **delete vs delete[]**: `new int[5]` + `delete p` (без `[]`) — UB (срабатывает не для всех типов, но хорошо показать sanitizer).
5. **Use-after-free**: освободить, потом использовать — классика багов безопасности (CVE).
Запусти каждый пример под `-fsanitize=address`. Покажи что sanitizer чётко указывает на место.

50–70 мин. Время жизни объекта и placement new.
Объект «начинает существовать» когда constructor завершился. «Заканчивает» когда destructor начался. Обращение к памяти объекта за пределами его времени жизни — UB.
```cpp
// Placement new: создать объект в уже выделенной памяти
alignas(int) char buf[sizeof(int)];
int* p = new(buf) int(42);     // создать int в buf без new-аллокации
p->~int();                      // явный вызов деструктора (редко нужен)
```
Зачем нужно: пулы памяти, контейнеры (std::vector использует placement new внутри).

70–82 мин. Выравнивание и паддинг.
```cpp
struct Bad { char c; int i; char c2; };    // sizeof = 12 (!) из-за паддинга
struct Good { int i; char c; char c2; };   // sizeof = 8
```
Процессор эффективнее читает данные, выровненные по их размеру. Компилятор добавляет паддинг автоматически. `alignof(T)` — требуемое выравнивание типа. `alignas(N)` — задать выравнивание вручную.
Практика: написать структуру, посчитать теоретический и реальный sizeof.
