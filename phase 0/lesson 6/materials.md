### new и delete

```cpp
// Одиночный объект:
int* p = new int(42);          // выделить + инициализировать
delete p;                       // уничтожить + освободить
p = nullptr;                    // обнулить (хорошая практика)

// Массив:
int* arr = new int[10]();      // выделить массив, zero-initialize
delete[] arr;                   // ОБЯЗАТЕЛЬНО delete[] для массивов

// Пользовательский тип:
struct Point { int x, y; };
Point* pt = new Point{1, 2};
delete pt;                      // вызовет ~Point(), потом освободит
```

**Правило**: каждый `new` — один `delete`. Каждый `new[]` — один `delete[]`. Никогда не путать.

### Классические баги динамической памяти

**Утечка памяти:**
```cpp
void leak() {
    int* p = new int(42);
    if (something_failed) return;  // p не освобождён!
    delete p;
}
```

**Висячий указатель (dangling pointer):**
```cpp
int* p = new int(5);
delete p;
// p всё ещё хранит старый адрес, но память уже «чужая»
*p = 10;  // UB — use-after-free
```

**Double-free:**
```cpp
int* p = new int(5);
delete p;
delete p;  // UB — повреждение кучи, возможен crash
```

**delete vs delete[]:**
```cpp
int* arr = new int[5];
delete arr;   // UB! Нужен delete[]
```

### Обнаружение через AddressSanitizer

```bash
g++ -fsanitize=address -g program.cpp -o program
./program
# При ошибке выводит подробный отчёт: тип ошибки, строка, стек вызовов
```

Valgrind (альтернатива, более медленный):
```bash
valgrind --leak-check=full ./program
# Детальный отчёт об утечках и ошибках доступа
```

### Время жизни объекта

Объект существует: после завершения конструктора → до начала деструктора. Обращение к памяти объекта вне этого периода — UB, даже если память физически не освобождена.

### Placement new

Создаёт объект в уже выделенном буфере без аллокации памяти:
```cpp
alignas(MyClass) char buf[sizeof(MyClass)];
MyClass* p = new(buf) MyClass(args);  // размещает в buf
p->~MyClass();                         // явно вызвать деструктор
// память buf освобождается автоматически (стек) или отдельно
```
Используется внутри `std::vector`, пулов памяти, кастомных аллокаторов.

### Выравнивание и паддинг структур

Процессор читает данные эффективнее если они выровнены по своему размеру (int по 4 байта, double по 8). Компилятор добавляет невидимый паддинг:

```cpp
struct Padded {
    char  c;   // 1 байт
               // 3 байта паддинга
    int   i;   // 4 байта
    char  c2;  // 1 байт
               // 3 байта паддинга (выравнивание struct)
};
// sizeof(Padded) == 12, не 6!

struct Packed {
    int   i;   // 4 байта
    char  c;   // 1 байт
    char  c2;  // 1 байт
               // 2 байта паддинга
};
// sizeof(Packed) == 8 — переставили поля от большего к меньшему
```

`alignof(T)` — минимальное выравнивание типа. `alignas(N)` — задать выравнивание переменной или члена структуры:
```cpp
alignas(64) char cache_line[64];  // выровнять по границе кэш-линии
```
