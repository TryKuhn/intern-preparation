0–5 мин. Зачем это всё.
Обсуди вопрос из пре-ридинга. Подведи: без веток два разработчика всё время конфликтуют, откат к предыдущей версии требует ручного архива, история изменений теряется. Git решает всё это системно. Добавь: бэкенд-команды живут в Git — без него нельзя попасть на стажировку.

5–25 мин. Модель данных Git.
Объясни концепцию, нарисуй на бумаге три кольца: рабочая директория → staging area → репозиторий → remote.
- Рабочая директория: обычные файлы на диске.
- Staging (индекс): «корзина» для следующего коммита, `git add` кладёт туда.
- Коммит: неизменяемый снимок, адресован SHA-хешем.
- Remote: копия репозитория на сервере (GitHub).
- HEAD: указатель на текущий коммит (или на ветку, которая указывает на коммит).
Покажи `git log --oneline --graph` на любом публичном репо — пусть видит, как история выглядит на практике.
Вопрос ей: если git хранит снимки, а не дельты — почему репозитории не занимают огромное место? (Ответ: объекты дедуплицируются по содержимому.)

25–50 мин. Базовые команды.
Практика прямо в терминале. Пусть создаст папку, сделает `git init`, добавит файл, сделает коммит.
- `git status` — самая важная команда, используй её после каждого шага.
- `git add file` vs `git add .` — объясни разницу: `add .` может захватить лишнее.
- `git diff` (до add) и `git diff --staged` (после add, до commit).
- `git log --oneline` — краткая история.
- `.gitignore`: создайте файл, добавьте `*.o` и `build/`, проверь что они игнорируются.
Подводный камень: студентки часто путают `git add .` и `git commit -a`. Объясни разницу.

50–70 мин. Ветки, merge, rebase.
- `git branch feature` + `git switch feature` (или `git checkout -b feature`).
- Сделать коммит на ветке, затем `git switch main` — покажи что в main изменений нет.
- `git merge feature` — fast-forward vs merge commit (нарисуй).
- **Merge vs rebase**: merge сохраняет историю буквально (создаёт merge-коммит), rebase переписывает историю так, будто ветка создавалась от последнего main. Золотое правило: не делать `rebase` общих веток.
- Конфликт: искусственно создайте конфликт (отредактируйте одну строку в двух ветках), сделайте merge, покажи маркеры `<<<<`, `====`, `>>>>`. Вместе разрешите.

70–82 мин. Удалёнка и откаты.
- `git remote add origin URL`, `git push -u origin main`, `git pull`, `git fetch`.
- PR-флоу: ветка → push → открыть PR на GitHub → reviewer → merge. Покажи в интерфейсе GitHub.
- Откаты — ключевые различия:
  - `git restore file` — отменить изменения в рабочей директории (не трогает историю).
  - `git reset --soft HEAD~1` — убрать последний коммит, изменения остаются в staging.
  - `git reset --mixed HEAD~1` — убрать коммит, изменения в рабочей директории (default).
  - `git reset --hard HEAD~1` — убрать коммит и все изменения (опасно!).
  - `git revert HEAD` — создаёт новый коммит, который отменяет изменения (безопасно для общих веток).
Подводный камень: `reset --hard` уничтожает работу без предупреждения. Приучи всегда делать `git status` перед.

82–90 мин. Итог и выдача ДЗ.
Сделайте вместе первый push на GitHub. Создай репозиторий `cpp-practice`, запушь что сделали сегодня. Объясни: это репо будет расти весь курс. Выдай домашку.
