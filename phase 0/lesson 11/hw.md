### A. Иерархия фигур (около 50 мин)

1. Реализуй иерархию: `Shape` (базовый, абстрактный) → `Circle`, `Rectangle`, `Triangle`.
   - `Shape`: виртуальные методы `area() const`, `perimeter() const`, виртуальный деструктор.
   - Каждая фигура хранит нужные размеры и реализует методы.
2. Создай `std::vector<std::unique_ptr<Shape>>` и добавь несколько фигур. Вызови `area()` через полиморфизм.
3. Добавь `virtual std::string type() const` в каждый класс.
4. Покажи slicing: скопируй `Circle` в `Shape` по значению. Выведи `type()` у копии — что вернёт?

### B. vtable и виртуальный деструктор (около 30 мин)

1. Без виртуального деструктора: создай класс `Base` с полем `data_` и деструктором с выводом. `Derived` наследует `Base` и добавляет `heap_data_ = new int[1000]` в конструкторе и delete[] в деструкторе. Создай через `Base* p = new Derived()`, удали через `delete p`. Покажи через valgrind/ASan что Derived деструктор не вызвался.
2. Добавь `virtual ~Base()`. Покажи что теперь оба деструктора вызываются.
3. Через `sizeof` покажи разницу между объектом с и без виртуальных функций.

### C. override, сокрытие имён, аргументы по умолчанию (около 30 мин)

1. Напиши базовый класс с виртуальной функцией `void process(int x)`. В наследнике напиши `void process(float x)` — без `override`. Покажи что при вызове через Base* вызывается Base::process, а не Derived::process. Теперь добавь `override` — получи ошибку компиляции.
2. Воспроизведи баг с аргументами по умолчанию: `virtual void show(int x = 1)` в Base и `void show(int x = 2) override` в Derived. Вызови через `Base*` — убедись что берётся дефолт из Base.
3. Покажи `using Base::process` для подъёма перегрузок из базового класса.

### D. Ромб (около 20 мин)

1. Создай иерархию A→B, A→C, D→B,C (без virtual). Попробуй обратиться к полю `A::x` через `D`. Получи ошибку неоднозначности.
2. Исправь через `virtual` наследование. Покажи что теперь один `A`.
3. Сравни sizeof D с virtual и без. Объясни разницу.
