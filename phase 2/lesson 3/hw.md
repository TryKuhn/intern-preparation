### A. Реализация (около 60 мин)

1. Реализуй `merge_sort(vector<int>&)`.
2. Реализуй `quick_sort(vector<int>&)` с random pivot.
3. Реализуй `counting_sort(vector<int>&, int max_val)`.
4. Напиши `is_sorted(const vector<int>&)` — проверка без std::is_sorted.
5. Протестируй все три сортировки на: пустом массиве, массиве из одного элемента, уже отсортированном, обратном, случайном из 100 000 элементов.

### B. Сложность и баги (около 30 мин)

1. Реализуй quicksort с pivot = последний элемент (без рандомизации). Создай массив 1,2,...,10000 и запусти. Что происходит (переполнение стека)? Исправь рандомизацией.
2. Почему `merge_sort` стабильна, а `quick_sort` нет? Создай пример который демонстрирует разницу.
3. Объясни: когда counting_sort применять нельзя?

### C. Компараторы (около 30 мин)

1. Отсортируй вектор пар по второму элементу, при равенстве — по первому убыванию.
2. Отсортируй файлы `struct File { string name; int size; time_t modified; }` по размеру, при равенстве — по дате изменения (новее сначала).
3. Реализуй stable sort через merge sort для структур.

### Самопроверка (около 15 мин, письменно в `selfcheck.md`)

1. Почему quicksort быстрее mergesort на практике при одинаковой O-сложности?
2. Что такое стабильная сортировка? Почему это важно?
3. Когда использовать counting sort?
4. Как std::sort защищается от O(n²)?
5. Рекуррентное соотношение merge sort → O(n log n): выведи.

### Критерий "сделано"
Все три сортировки работают корректно, рандомизированный quicksort не падает на отсортированных данных, компараторы корректно применены.
