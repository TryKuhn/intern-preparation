0–10 мин. Зачем это всё.
Обсуди: N=10⁵, O(n²) → 10^10 операций → ~100 секунд. Не пройдёт. O(n log n) → 10⁵ × 17 ≈ 1.7×10⁶ → мгновенно. Умение прикинуть сложность до написания кода — фундаментальный навык.

10–35 мин. Big-O и класса O/Θ/Ω.
- O(f): верхняя граница — алгоритм не хуже чем f.
- Ω(f): нижняя граница — алгоритм не лучше чем f.
- Θ(f): точная оценка — и верхняя, и нижняя.
На практике обычно говорят O().

Таблица «прикидки»:
```
N ≤ 10    → O(n!) подойдёт (перебор всех перестановок)
N ≤ 20    → O(2^n) (экспоненциальный перебор)
N ≤ 500   → O(n³)
N ≤ 5000  → O(n²)
N ≤ 10⁶   → O(n log n)
N ≤ 10⁸   → O(n)
N ≤ 10¹⁸  → O(log n) или O(1)
```
Правило: ~10⁸ простых операций ≈ 1 секунда (грубо, зависит от железа и операций).

35–60 мин. Оценка конкретных фрагментов кода.
Разобрать вместе:
```cpp
// O(n):
for (int i = 0; i < n; i++) sum += a[i];

// O(n²):
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) ...

// O(n log n) — бинарный поиск в цикле:
for (int i = 0; i < n; i++) binary_search(a, target);

// O(log n) — бинарный поиск:
int lo = 0, hi = n-1;
while (lo <= hi) { int mid = (lo+hi)/2; ... }

// O(2^n) — рекурсивный Фибоначчи:
int fib(int n) { return fib(n-1) + fib(n-2); }
```
