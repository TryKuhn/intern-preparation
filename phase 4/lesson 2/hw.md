### A. Первый Dockerfile (около 40 мин)
1. Напиши Dockerfile для C++ "Hello, World!" программы. Собери образ: `docker build -t hello-cpp .`. Запусти: `docker run hello-cpp`.
2. Продемонстрируй кэш слоёв: измени исходник, пересобери — покажи что пересобирается только с нужного слоя. Теперь поставь COPY всего исходника в начало — покажи что кэш инвалидируется полностью.
3. Сравни `CMD` и `ENTRYPOINT`: напиши Dockerfile с ENTRYPOINT. Переопредели команду при `docker run`. Убедись в разнице поведения.

### B. Multi-stage build (около 50 мин)
1. Возьми C++ проект из Phase 4 Lesson 1. Напиши multi-stage Dockerfile: stage builder с g++/cmake, stage runtime с минимальным образом.
2. Сравни размеры через `docker images`. Убедись что runtime image ≪ builder.
3. Добавь `.dockerignore` — исключи build/, .git/, объектные файлы. Убедись что `docker build` игнорирует их.
4. Запусти контейнер с проброском порта: приложение на порту 8080 внутри → доступно на хосте.

### C. Volumes и переменные окружения (около 30 мин)
1. Создай контейнер с базой данных (postgres:15), примонтируй volume для данных:
   ```bash
   docker run -d --name pg -e POSTGRES_PASSWORD=pass \
     -v pgdata:/var/lib/postgresql/data -p 5432:5432 postgres:15
   ```
2. Подключись к БД, создай таблицу, добавь данные. Удали контейнер. Создай новый с тем же volume — данные должны сохраниться.
3. Передай DB_HOST, DB_PORT, DB_NAME через переменные окружения в своё C++ приложение.

### Самопроверка (около 15 мин, письменно в `selfcheck.md`)
1. Чем контейнер отличается от виртуальной машины?
2. Что такое слой Docker и как работает кэш?
3. Зачем multi-stage build?
4. CMD vs ENTRYPOINT — объясни разницу с примером.
5. Зачем volume? Что происходит с данными без него?

### Критерий "сделано"
Multi-stage Dockerfile создаёт runtime образ меньше 100 МБ, кэш слоёв продемонстрирован, volume с данными переживает удаление контейнера.
